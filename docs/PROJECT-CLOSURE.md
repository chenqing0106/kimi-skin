# kimi-skin 项目收尾记录

2026 年 8 月 18 日，kimi-skin 停止维护。

这个项目最初想做一件简单的事：不修改 Kimi.app，不破坏签名，也不接触用户数据，只通过本机调试接口给 Kimi Work 加上可以创作、切换和恢复的主题。

最后实际完成的不只是一组 CSS。项目跑通了主题发现与校验、CDP 注入、热切换、文件监听、失败回滚、普通模式恢复、进程归属验证、签名基线检查、版本表面探测，以及受限 CSS 和本地素材策略。仓库中的主题、预览图和设计记录保留原样。

项目停止不是因为某个主题失效。Kimi 3.1.9 的打包主进程开始检查启动参数，发现 `--remote-debugging-port` 后会直接退出。这个参数正是整个注入链路的入口。继续运行只会变成追逐上游限制，或者走向修改应用包、破坏签名等更侵入的方案，已经偏离项目原本的边界。

因此最终决定是：不绕过限制，不修改 Kimi.app，不把一次实验继续包装成可长期维护的工具。CLI 只允许最后实际验证过的 Kimi 3.1.7、3.1.8；3.1.9 和未知后续版本会在重启前停止。

这次留下的核心经验也很具体：依附其他产品做扩展时，先确认入口是否属于官方承诺的能力，评估上游能否通过一次更新让核心链路失效，并在扩大投入前明确实验和长期产品的边界。

项目没有得到一个能持续使用的结局，但完整验证了这条路线能做到什么、又会在哪里失去控制。代码留在这里，作为这次实验本身的记录。
