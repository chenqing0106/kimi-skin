# 创建前的渐进式校准

用于创建新主题或大幅改变现有主题方向。目标是补齐高影响决策，不是让用户填写完整问卷。

## 提问原则

1. 先提取用户已经说清楚的选择，不重复询问。
2. 只问答案会明显改变实现路径的问题，通常一次集中问 2–3 个。
3. 优先确认复杂程度和背景；动效、交互与组件按主题语境选择性推荐。
4. 用户说“你决定”时给出推荐设计摘要，不继续追问。
5. 在用户确认摘要前只讨论方案，不创建或覆盖主题文件。

## 决策维度

### 复杂程度

- **基础**：配色、字体、表面层级；不增加额外图片素材和明显动画。
- **完整**：覆盖主要页面，加入背景材质和少量 CSS 动效。
- **表现型**：定制素材、标志性视觉、明显但克制的动效，以及适合主题时的受控交互或内置组件。

复杂程度决定投入和覆盖范围，不自动开启所有增强。用户可以要表现型视觉而不要组件，也可以要基础视觉加额度显示。

### 背景

- 保留原背景或只调整颜色。
- 使用 CSS 渐变、纹理和程序化图形。
- 使用当前环境的图像生成能力创建本地背景。
- 使用用户提供的图片。

创建新主题且用户没有说明背景时应询问。修改局部样式或用户已经说“不改背景”时跳过。

### 动效与状态交互

- CSS 动效适合营造漂浮、闪烁、呼吸、扫描、噪点和缓慢位移等效果；始终提供 `prefers-reduced-motion` 降级。
- 只有主题存在自然双态时才推荐 `rootStateToggle`，例如昼/夜、自然/数字、普通/ASCII。说明固定为双击触发，并说明如何恢复。
- 不要把普通 hover、focus 视觉反馈包装成需要用户选择的“高级交互”。
- 禁止主题级 JavaScript；当前受控能力无法表达的交互应报告为 harness 能力缺口。

### 功能组件

只推荐 `themes/README.md` 当前列出的内置 widget。额度组件适合终端、HUD、控制台、工作台或数据面板语境；纸张、自然、极简等主题通常不主动询问，除非用户提到额度或工作状态。

主题只能选择内置组件并设计其 CSS，不能提供 HTML、脚本、接口名或自定义数据源。用户需要新组件类型时，说明这属于独立的 harness 功能开发，不在主题创建范围内。

## 推荐提问方式

根据缺口自然组织问题，不照抄固定问卷。例如用户只说“做一个森林主题”时可以问：

1. 想做基础、完整还是表现型？
2. 背景更希望是 CSS 绘制的抽象森林，还是 AI 生成的插画？
3. 如果选择表现型，是否喜欢双击切换昼夜？

用户说“做一个简单纯色主题，不要动画”时，不再询问复杂程度、背景或动效，只补问真正影响范围的事项。

确认前用一小段摘要复述最终选择：核心概念、复杂程度、背景来源、动效强度、交互、组件、页面范围和明确不做的内容。

## AI 图片素材流程

用户明确选择 AI 图片后：

1. 检查当前环境是否提供图像生成 skill 或工具；优先按该工具自身说明调用，不写死特定供应商接口。
2. 从已确认的视觉系统整理提示词，先确认构图、色彩、留白和内容可读区域。需要探索时先生成低成本候选，确认方向后再生成正式版本。
3. 将最终文件保存到 `themes/<theme-id>/assets/`，使用稳定、语义化的文件名；不要把临时图和失败版本留在主题目录。
4. 必要时调整尺寸或压缩。manifest 背景必须小于 10 MiB；CSS 引用的普通素材遵守项目文档中的单文件限制。
5. 在 `ASSETS.md` 记录最终文件、生成工具、提示词、生成日期、后处理和公开分发许可。
6. 在 `theme.json` 或 CSS 中使用相对路径引用，并运行 `validate` 与 `check-theme`。

如果当前环境没有图像生成能力，明确说明并让用户选择 CSS/程序生成或上传图片，不声称已经生成素材。
