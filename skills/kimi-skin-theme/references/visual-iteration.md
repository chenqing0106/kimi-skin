# 视觉迭代方法

本文用于创建新主题、根据参考图调整主题，以及诊断“代码改了但效果没有变好”的情况。

## 1. 先定义视觉系统

不要直接把形容词翻译成大量 CSS。先确定：

- 一句核心概念
- 3–6 个语义颜色
- 字体与字号关系
- 表面层级：背景、侧栏、内容、浮层、输入框
- 一种主要材质
- 一个最有辨识度的元素
- 原生内容、头像、图片和功能图标如何保留

将这些决定写入 `DESIGN.md`，并列出本轮明确不处理的内容。已有主题可以帮助理解接口，但不要让它替代本次视觉判断。

## 2. 实现视觉方向

根据主题概念自主决定实现顺序，不必机械地先换完所有 token。可以从最能验证方向的部分开始，例如背景构图、字体系统、主要材质或标志性元素，再补齐内容表面和交互状态。

表现型主题至少应有一个不依赖换色的标志性视觉。基础层级、可读性和交互状态仍需成立，但不要用完整 token 换色代替设计。

## 3. 根据真实画面判断

优先比较：

- 视觉重心是否明确
- 是否仍然只是默认 Kimi 换色
- 文字与控件是否可读
- 表面层级是否能一眼区分
- 最有辨识度的元素是否真的出现
- 装饰是否压过内容
- hover、active、focus、disabled 是否仍可区分

如果整体方向不成立，可以一次重构字体、材质与构图；如果方向成立但局部有问题，再做小范围调整。

## 4. 效果没有改出来时

按顺序排查，不要继续随机添加 CSS：

1. 用 `status` 确认当前运行的主题路径和 Watcher。
2. 用 `reload` 排除热重载没有发生。
3. 用 `validate` 和 `check-theme` 排除加载失败或 Safe CSS 拒绝。
4. 在真实界面确认目标元素和选择器存在，不根据类名猜测。
5. 检查规则是否被更高优先级样式覆盖。
6. 确认修改影响的是正确页面、路由和状态。
7. 仍然无效时，把它记录为明确的选择器或系统问题，不用全局规则兜底。

常见判断：

- 完全没有变化：优先检查主题路径、重载、选择器和层叠优先级。
- 只有部分页面变化：检查路由条件和对应表面是否实际渲染。
- 颜色正确但仍显得普通：检查层级、材质、构图和辨识元素，而不是继续增加颜色。
- 画面很满：减少装饰种类、对比层级和同时竞争的视觉焦点。
- 内容不可用：先恢复交互和可读性，再继续审美调整。

## 5. 最小检查面

至少实际查看：

- 主页与输入框
- 一个真实内容页面，只检查呈现，不在记录或报告中复述文本
- 用户消息容器、工具卡或代码块的布局与状态，不提取其中内容
- 插件或定时任务页
- 菜单、弹层和滚动区域
- hover 与键盘 focus
- 较窄窗口
- `prefers-reduced-motion`

页面当前没有对应内容时，明确标记未检查，不以 CSS 中存在选择器代替视觉验证。

## 6. 完成标准

- 用户确认视觉方向成立。
- 校验命令通过。
- 必需表面有覆盖且真实页面可用。
- 迭代主要剩余审美取舍，而不是重复解决加载、路径和选择器错误。
- 交付说明包含已检查范围与已知遗漏。
