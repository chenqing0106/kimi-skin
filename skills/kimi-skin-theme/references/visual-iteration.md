# 视觉迭代方法

本文用于创建新主题、根据参考图调整主题，以及诊断“代码改了但效果没有变好”的情况。

## 1. 先定义视觉系统

不要直接把形容词翻译成大量 CSS。先确定：

- 一句核心概念
- 3–6 个语义颜色
- 字体与字号关系
- 表面层级：背景、侧栏、内容、浮层、输入框
- 一种主要材质
- 一个最有辨识度的元素
- 原生内容、头像、图片和功能图标如何保留

将这些决定写入 `DESIGN.md`，并列出本轮明确不处理的内容。

## 2. 按层实现

推荐顺序：

1. 根背景与语义变量
2. 页面外壳、侧栏和主内容层级
3. 输入框、按钮和交互状态
4. 内容页、代码块、弹层和滚动区域
5. 装饰素材与动效
6. 小窗口和 reduced motion

先让基础层级成立，再增加装饰。不要用装饰掩盖对比度、选择器或结构问题。

## 3. 根据真实画面判断

每轮迭代写下一个明确假设，例如：

> 侧栏与主内容明度太接近，导致信息层级消失。本轮只调整两者的背景与边界。

修改后只检查这个假设是否成立。不要同一轮顺便改变字体、背景图和动画。

优先比较：

- 视觉重心是否明确
- 文字与控件是否可读
- 表面层级是否能一眼区分
- 最有辨识度的元素是否真的出现
- 装饰是否压过内容
- hover、active、focus、disabled 是否仍可区分

## 4. 效果没有改出来时

按顺序排查，不要继续随机添加 CSS：

1. 用 `status` 确认当前运行的主题路径和 Watcher。
2. 用 `reload` 排除热重载没有发生。
3. 用 `validate` 和 `check-theme` 排除加载失败或 Safe CSS 拒绝。
4. 在真实界面确认目标元素和选择器存在，不根据类名猜测。
5. 检查规则是否被更高优先级样式覆盖。
6. 确认修改影响的是正确页面、路由和状态。
7. 仍然无效时，把它记录为明确的选择器或系统问题，不用全局规则兜底。

常见判断：

- 完全没有变化：优先检查主题路径、重载、选择器和层叠优先级。
- 只有部分页面变化：检查路由条件和对应表面是否实际渲染。
- 颜色正确但仍显得普通：检查层级、材质、构图和辨识元素，而不是继续增加颜色。
- 画面很满：减少装饰种类、对比层级和同时竞争的视觉焦点。
- 内容不可用：先恢复交互和可读性，再继续审美调整。

## 5. 最小检查面

至少实际查看：

- 主页与输入框
- 一个真实内容页面
- 用户消息、工具卡或代码块
- 插件或定时任务页
- 菜单、弹层和滚动区域
- hover 与键盘 focus
- 较窄窗口
- `prefers-reduced-motion`

页面当前没有对应内容时，明确标记未检查，不以 CSS 中存在选择器代替视觉验证。

## 6. 完成标准

- 用户确认视觉方向成立。
- 校验命令通过。
- 必需表面有覆盖且真实页面可用。
- 迭代主要剩余审美取舍，而不是重复解决加载、路径和选择器错误。
- 交付说明包含已检查范围与已知遗漏。
